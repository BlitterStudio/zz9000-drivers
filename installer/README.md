# ZZ9000 Commodore Installer

This is a Commodore Installer script drawer that end users run on an
AmigaOS system to install the ZZ9000's drivers, tools and config
files. It's bundled into every GitHub Release zip.

## Layout

```
installer/
├── ZZ9000Installer.info              Drawer icon
└── ZZ9000Installer/
    ├── Install ZZ9000                Installer script (what the user double-clicks)
    ├── Install ZZ9000.info           Script icon
    ├── Tools.info                    Sub-drawer icon
    ├── Docs/
    │   ├── ahi.guide                Audio tunables doc generated by CI
    │   ├── ZZTop.guide              ZZTop control-panel manual generated by CI
    │   ├── tools.guide              Command-line tool manual generated by CI
    │   ├── usb-poseidon.guide       Poseidon setup doc generated by CI
    │   ├── ZZCapture.guide          Native capture diagnostic manual generated by CI
    │   ├── sdk.guide                SDK runtime doc generated by CI
    │   ├── ZZPlay.guide             ZZPlay manual from the SDK payload
    │   └── amissl.guide             Accelerated AmiSSL doc generated by CI
    ├── Devs/
    │   ├── Picasso96Settings         Zorro II-safe P96 screenmode config  (committed)
    │   ├── Picasso96Settings-Z3      Zorro III high-memory P96 config  (committed)
    │   ├── USBHardware/              ← zzusbhw.device populated by CI
    │   ├── NetInterfaces/
    │   │   └── ZZ9000Net             Roadshow NetInterface template  (committed)
    │   ├── AHI/                      ← zz9000ax.audio populated by CI
    │   ├── AudioModes/               ← ZZ9000AX populated by CI
    │   └── Networks/                 ← ZZ9000Net.device populated by CI
    ├── Classes/
    │   └── DataTypes/               ← zz9k-picture.datatype populated by CI
    ├── Storage/
    │   └── DataTypes/               ← JPEG/PNG datatype descriptors populated by CI
    ├── Libs/
    │   ├── MHI/                      ← mhizz9000.library populated by CI
    │   ├── Picasso96/                ← ZZ9000.card populated by CI
    │   ├── zz9k.library             ← populated by CI
    │   ├── mpega.library            ← populated by CI
    │   └── AmiSSL/
    │       ├── 68020-40/            ← amissl_v362.library (68020/030/040) populated by CI
    │       └── 68060/               ← amissl_v362.library (68060) populated by CI
    └── Tools/
        ├── ZZTop.info                Icon  (committed, generated by
        │                                    tools/make-zztop-icon.py)
        └──                           ← ZZTop, ZZScanlines, ZZFwUpdate,
                                        ZZNetStats, ZZDiag, ZZCapture,
                                        zz9k-info, zz9k-services, zz9k-view,
                                        zz9k-mp3, zz9k-cryptobench,
                                        zz9k-archive,
                                        ZZPlay + ZZPlay.info
                                        populated by CI
1. Unpack the release LHA on the Amiga and open `ZZ9000Installer`.
2. Double-click `Install ZZ9000`.
3. For RTG support, install Picasso96 first and select either the `Altais` or
   `ZZ9000` monitor. The script stops when `Libs:Picasso96/rtg.library` is
   older than version 40 or neither monitor file is present.
4. Choose the Zorro II-safe profile unless the machine has a Zorro III
   ZZ9000. The Zorro III profile enables the 1920x1080x32 screen mode.
5. Answer the optional USB, SDK, AmiSSL, ZZCapture, and command-path prompts
   as needed.

At Installer user level 2 or higher, the script asks where to create the
`ZZ9000` program drawer and where to put general manuals. The defaults are
`SYS:Utilities/ZZ9000` and that same drawer. `ZZTop`, `ZZPlay`, and their
manuals always go in the program drawer.

## What the script installs

| Component | Source in `ZZ9000Installer/` | Destination and behaviour |
| --- | --- | --- |
| Picasso96 driver | `Libs/Picasso96/ZZ9000.card` | Offers to install or replace `Libs:Picasso96/ZZ9000.card`. |
| Monitor and P96 settings | Existing `Devs:Monitors/Altais`; `Devs/Picasso96Settings` or `Devs/Picasso96Settings-Z3` | Creates `Devs:Monitors/ZZ9000` from `Altais` when needed, removes the old `Altais` file after confirmation, sets `BOARDTYPE=ZZ9000`, `FAKENATIVEMODES=No`, and `DISPLAYCHAIN=Yes`, then installs the selected profile as `Devs:Picasso96Settings`. |
| Poseidon USB | `Devs/USBHardware/zzusbhw.device` | Optional. Installs to `Devs:USBHardware/`; if that drawer is absent, offers to create it. |
| Network | `Devs/Networks/ZZ9000Net.device`; `Devs/NetInterfaces/ZZ9000Net` | Saves the entered MAC address in `ENVARC:ZZ9K_MAC`, installs the SANA-II driver in `Devs:Networks/`, and installs the DHCP Roadshow template in `Devs:NetInterfaces/`. |
| AHI and MHI audio | `Devs/AHI/zz9000ax.audio`; `Devs/AudioModes/ZZ9000AX`; `Libs/MHI/mhizz9000.library` | Installs the AHI subdriver in `Devs:AHI/`, its AudioMode in `Devs:AudioModes/`, and the MHI library in `LIBS:MHI/`. |
| SDK runtime | `Libs/zz9k.library`; `Libs/mpega.library`; `Classes/DataTypes/zz9k-picture.datatype`; `Classes/DataTypes/zz9k-sound.datatype`; `Storage/DataTypes/`; `Tools/zz9k-#?`; `Tools/ZZPlay#?` | Offered only when `zz9k.library` is in the release drawer. Installs `zz9k.library` and optional `mpega.library` in `LIBS:`, the picture and sound datatype classes in `SYS:Classes/DataTypes/`, the JPEG, PNG, WebP, MP3, FLAC, and Ogg Vorbis descriptors in inactive `SYS:Storage/DataTypes/`, the `zz9k-*` commands in `C:`, and `ZZPlay` in the program drawer. |
| Accelerated AmiSSL | `Libs/AmiSSL/68020-40/amissl_v362.library`; `Libs/AmiSSL/68060/amissl_v362.library` | Offered only when a staged build and `LIBS:AmiSSL/amissl_v362.library` already exist. Backs up the installed library once, then installs the chosen CPU build in `LIBS:AmiSSL/`. |
| Control panel | `Tools/ZZTop` | Installs in the program drawer. |
| Command-line tools | `Tools/ZZScanlines`; `Tools/ZZFwUpdate`; `Tools/ZZNetStats`; `Tools/ZZDiag`; `Tools/ZZNetReady` | Installs each command in `C:`. |
| Native capture diagnostic | `Tools/ZZCapture` | Optional. Installs in `C:` when selected. |

When `ZZTop` or `ZZPlay` is installed, the final prompt defaults to adding the
program drawer to `S:User-Startup`. It writes a replaceable `;BEGIN ZZ9000` /
`;END ZZ9000` block containing `Path <drawer> ADD`, so new Shells opened after
the next reboot can find those programs by name.

### Firmware bundles

The installer does not write firmware to the card. Use `ZZTop` or
`ZZFwUpdate` after installation with an unpacked matching firmware release.
They install the release's `ZZ9K/*.ZZM` modules before `BOOT.bin` and leave
the card's `ZZ9000.CFG` unchanged. On firmware that lacks the `ZZ9K/` updater
capability, install `BOOT.bin`, reboot, then run the same release install
again to add the optional modules.

## Configuration, upgrades, and troubleshooting

### Picasso96

`ZZ9000.card` 2.4 and later uses the `BT_MNT_ZZ9000` board type. On the first
upgrade of an existing, unmarked `Devs:Picasso96Settings`, the script creates
`Devs:Picasso96Settings.pre-ZZ9000-2.4` and, if absent,
`Devs:Picasso96Settings.bak` before replacing the settings file. It records the
installation in `ENVARC:ZZ9000.P96Settings`, so later runs skip that migration.
Keep a separate copy of custom settings before selecting either supplied
profile.

`Picasso96Settings` is the shared Zorro II and Zorro III profile.
`Picasso96Settings-Z3` is for Zorro III only. Both contain the monitor DPMS
Standby, Suspend, and Active Off capabilities used by `ZZ9000.card`. The stock
templates use a 148571429 Hz pixel clock for 1920x1080. See the
[output and refresh profiles](../README.md#scandoubler-output-and-refresh) for
firmware and card requirements.

Native chipset video normally starts with `filtered_60`: 800x600 for PAL input
and 720x480 for NTSC input, both at nominal 60 Hz. Use ZZTop's **Display** page
to select **Output** and **Refresh**, then save the setting. Enable
**Settings → Advanced controls** to access the **Capture** page. Remove legacy
`ENVARC:ZZ9000-VCAP-800x600`, `ENVARC:ZZ9000-NS-VSYNC`, and
`ENVARC:ZZ9000-NS-VSYNC-NTSC` overrides when ZZTop manages native output.

### Poseidon USB

Install Poseidon before selecting `zzusbhw.device`. If Poseidon does not bind
the device after installation, open Trident's Hardware page, add
`zzusbhw.device` with unit `0`, save, then reboot or restart Poseidon. Read
`usb-poseidon.guide` for setup and fault diagnosis.

### Network and audio

The installer writes its default MAC address prompt to `ENVARC:ZZ9K_MAC`. To
change it later, edit that file. Firmware 2.3 and later can also read `mac`
from `ZZ9000.CFG`; the ENV value takes precedence.

Use ZZTop's Audio page for normal audio settings. `ZZ9K_MIX_LEVELS` and
`ZZ9000AX-NOLPF` are no longer used. `ENV:ZZ9K_INT2` remains available for
interrupt-conflict troubleshooting and affects both audio drivers.

### SDK runtime and AmiSSL

The SDK runtime needs SDK-service firmware. On matched Zorro II firmware,
bitstream, SDK payload, and driver sets, SDK clients share one host window:
16 KiB on current generation-2 layouts, which reserve the other 48 KiB for the
audio direct ring, and 64 KiB on generation 1. The 4 MiB profile supports one
bounded 224 KiB `ZZPlay` PIP source; the 2 MiB profile has no video PIP. Concurrent accelerated operations can
contend for that window. Legacy descriptor-free 4 MiB compatibility keeps the
fixed 64 KiB window without negotiated layout or PIP; legacy 2 MiB and unknown
sizes reject it.

The accelerated AmiSSL option replaces
`LIBS:AmiSSL/amissl_v362.library` only after preserving it as
`amissl_v362.library.bak`, unless that backup already exists. Choose
`68020/030/040/080 or MorphOS` for 68020, 68030, 68040, or Apollo 68080, and
choose `68060 or Amithlon` for 68060 or Amithlon. To revert, delete the
accelerated library and rename the `.bak` file. Supported TLS work uses the
ZZ9000 path; unsupported algorithms use AmiSSL's software provider.

### ZZCapture

`ZZCapture info` and `ZZCapture observe` collect native-video timing evidence
without changing capture phase. `phase`, `check`, `startup`, and `calibrate`
are experimental A4000/C28 diagnostics. Use them only with the matching
firmware and bitstream, run `Stack 32768` first, and read `ZZCapture.guide`.
The tool does not save `ZZ9000.CFG`.

## Release contents and local packaging

The release archive contains `README.md`, `ZZ9000Installer.info`, and the
`ZZ9000Installer/` drawer at its root. Driver and tool binaries are contained
inside that drawer, not duplicated at the archive root. Release packaging also
converts text manuals and the installer script from repository UTF-8 to
Amiga-compatible ISO-8859-1.

The repository keeps icons and configuration templates. CI or local packaging
supplies binary payloads, generated manuals, SDK runtime files, and the
per-CPU AmiSSL builds. A fresh clone is therefore not an installable release.
For a local package with the same staging layout, build the required components
and run:

```sh
make package-local
```

Only **icons and configuration templates** are committed. Every binary
payload is built by CI and copied into this tree during the release
assembly step (see `.github/workflows/ci.yml`, `release` job). The
`.gitignore` rules on `*.card`, `*.device`, `*.audio`, etc. keep any
locally-populated binaries from accidentally being committed back.

This means a fresh `git clone` will **not** produce a runnable
Installer drawer on its own — CI must have populated it, or you must
copy the binaries in by hand.

`ZZ9000.card` 2.4 and newer uses the native `BT_MNT_ZZ9000` Picasso96
board type. Upgrade tests should copy one of the committed
`ZZ9000Installer/Devs/Picasso96Settings*` files along with the new RTG
driver; old settings saved under the legacy `uaegfx` board type are not
guaranteed to attach to the new driver identity. The default
`Picasso96Settings` profile is safe for Zorro II and Zorro III. The
`Picasso96Settings-Z3` profile enables 1920x1080x32 and should only be
installed on Zorro III systems. Both profiles advertise the monitor's
Picasso96 DPMS Standby, Suspend, and Active Off capabilities so DPMS
utilities can reach the firmware-gated `ZZ9000.card` callback.
The installer backs up the previous settings file as
`Devs:Picasso96Settings.pre-ZZ9000-2.4` before installing the migrated
settings file.
The current 1920x1080 timing uses a 148571429 Hz pixel clock in both stock
templates, matching the updated firmware and RTG callbacks. Preserve a
backup of custom settings; do not overwrite them merely to test the
native Scandoubler output.


Native Amiga chipset video normally defaults to `filtered_60`: PAL input
uses 800x600 and NTSC input uses 720x480, both at nominal 60 Hz. The
nonstandard-sync firmware variant defaults to PAL timing. In ZZTop, open
**Settings → Scandoubler…**, select **Output** and **Refresh**, then **Save**
and power-cycle. **Capture…** in that window owns sampling, framing and
calibration; the **Other Settings…** window no longer contains native-video
controls. The Settings menu also opens Audio and Other Settings when the
main buttons are off-screen.

Centered 1920x1080 output preserves the 1280x1024 native picture and offers
nominal 60 Hz or 50 Hz only with matching firmware/bitstream capabilities.
Install the matching `ZZ9000.card` and ZZTop as well. These choices are
separate from Picasso96 RTG screenmodes; see the
[profile table and compatibility rules](../README.md#scandoubler-output-and-refresh).
Remove legacy `ENVARC:ZZ9000-VCAP-800x600`, `ENVARC:ZZ9000-NS-VSYNC`,
and `ENVARC:ZZ9000-NS-VSYNC-NTSC` overrides when using ZZTop to manage
native output.

Release packaging converts the README, manuals, and installer script to
Amiga-compatible ISO-8859-1 (Latin-1), replacing Unicode punctuation and
diagrams with plain-text equivalents. Repository sources remain UTF-8.

The SDK runtime payloads (`zz9k.library`, the ARM-accelerated
`mpega.library` drop-in, the `zz9k-picture.datatype` plus its inactive
JPEG/PNG descriptors under `Storage/DataTypes`, and the `zz9k-#?` CLI
tools) are built from the pinned zz9000-sdk ref and populated by CI.
They need the SDK-service ZZ9000 firmware to do anything useful. On
Zorro 2 boards, current matched firmware, bitstream, SDK payloads, and drivers
negotiate a shared 64 KiB host window. It supports compact audio/MP3,
streamed image/DataType, archive, and AmiSSL clients on the shipped 2 MiB and
4 MiB profiles. The 4 MiB profile also provides one bounded 224 KiB ZZPlay PIP
source; the 2 MiB profile has no video PIP. Keep the complete release set
matched: invalid or unacknowledged generation-1 descriptors disable the
negotiated paths. Descriptor-absent legacy 4 MiB compatibility retains only the
historical fixed 64 KiB host window, without negotiated layout or PIP; legacy
2 MiB and unknown sizes reject it. The host window is shared across clients, so
concurrent accelerated operations can contend.

`ZZCapture` is offered as a separate, optional CLI-tool choice. Its `info` and
`observe` commands collect native-video timing evidence without changing the
capture phase. The `phase`, `check`, `startup`, and `calibrate` commands are
experimental A4000/C28 diagnostics and require the exact matched firmware and
bitstream plus `Stack 32768`. Read `Docs/ZZCapture.guide` before using
them; a matched-firmware refusal is a package/version problem, not a check to
bypass.

When installing the ZZ9000-accelerated `amissl.library`, the installer
first backs up the stock `LIBS:AmiSSL/amissl_v362.library` to
`amissl_v362.library.bak` — only if no `.bak` already exists, so
re-running the installer always preserves the genuine original — then
installs the build matching the host CPU (`Libs/AmiSSL/68020-40/` for
68020/030/040 and the Apollo 68080, `Libs/AmiSSL/68060/` for the 68060),
detected exactly as AmiSSL's own installer does. To revert, delete the
accelerated `amissl_v362.library` and rename the `.bak` back. The
accelerated library covers supported TLS handshake and record crypto;
unsupported algorithms automatically stay on AmiSSL's software provider.

## Trying the installer locally

If you want to test the installer with your own local builds (rather
than downloading a release zip), copy each artifact into the drawer
using the same layout CI uses:

```sh
SDK_SRC=../zz9000-sdk          # a zz9000-sdk checkout; supplies scripts/md2guide.py
INST=installer/ZZ9000Installer
install -Dm644 rtg/ZZ9000.card                 "$INST/Libs/Picasso96/ZZ9000.card"
install -Dm644 mhi/mhizz9000.library           "$INST/Libs/MHI/mhizz9000.library"
install -Dm644 usb-poseidon/zzusbhw.device     "$INST/Devs/USBHardware/zzusbhw.device"
install -Dm644 net/ZZ9000Net.device            "$INST/Devs/Networks/ZZ9000Net.device"
install -Dm644 ahi/driver/zz9000ax.audio       "$INST/Devs/AHI/zz9000ax.audio"
install -Dm644 ahi/driver/ZZ9000AX             "$INST/Devs/AudioModes/ZZ9000AX"
install -Dm755 ZZTop/ZZTop                     "$INST/Tools/ZZTop"
install -Dm755 ZZScanlines/ZZScanlines         "$INST/Tools/ZZScanlines"
install -Dm755 ZZFwUpdate/ZZFwUpdate           "$INST/Tools/ZZFwUpdate"
install -Dm755 net/ZZNetStats/ZZNetStats       "$INST/Tools/ZZNetStats"
install -Dm755 ZZDiag/ZZDiag                   "$INST/Tools/ZZDiag"
install -Dm755 ZZCapture/ZZCapture             "$INST/Tools/ZZCapture"
python3 "$SDK_SRC/scripts/md2guide.py" --name ahi ahi/README.md          "$INST/Docs/ahi.guide"
python3 "$SDK_SRC/scripts/md2guide.py" --name usb-poseidon \
  usb-poseidon/README.md                                                "$INST/Docs/usb-poseidon.guide"
python3 "$SDK_SRC/scripts/md2guide.py" --name ZZCapture \
  ZZCapture/README.md                                                   "$INST/Docs/ZZCapture.guide"
```

The SDK runtime payloads and the per-CPU accelerated
`amissl_v362.library` are not produced by the lines above: they come
from `sdk/out` and `amissl/out` after their own builds. The easiest way
to stage everything (drivers, SDK payloads, and both amissl builds) into
the drawer exactly as CI does is `make package-local`, which runs
`tools/package-local.sh`.

Then copy the `installer/` tree onto your Amiga and double-click
`Install ZZ9000`.

For a direct RTG-only test, copy `rtg/ZZ9000.card` to
`Libs:Picasso96/` and copy
`installer/ZZ9000Installer/Devs/Picasso96Settings` to `Devs:`.

## Release bundle layout

The CI release job (tag push `v*`) produces a zip with the installer
contents at the package root:

```
zz9000-drivers-<tag>/
├── README.md
├── ZZ9000Installer.info
└── ZZ9000Installer/
```

Driver and tool binaries are not duplicated as loose files at the zip
root; they live in the exact drawer paths consumed by `Install ZZ9000`.

The release job also copies component docs into `ZZ9000Installer/Docs/`:
`ahi-README.md` covers the remaining audio ENV tunable
(`ZZ9K_INT2`) and the removed `ZZ9K_MIX_LEVELS` /
`ZZ9000AX-NOLPF` variables,
`usb-poseidon-README.md` covers Poseidon registration and
troubleshooting, `sdk-README.md` documents the SDK runtime payloads,
`ZZCapture-README.md` documents the native capture diagnostic and its matched
firmware requirement, and `amissl-README.md` documents the accelerated AmiSSL
build.

## What doesn't go through this Installer

The CI-built artifact below is **not** handled by this Installer script
because it doesn't live on the AmigaOS filesystem:

| Artifact            | Install path                                                   |
|---------------------|----------------------------------------------------------------|

## Updating the script

- The script lives at `installer/ZZ9000Installer/Install ZZ9000` and
  is plain text (Commodore Installer LISP-like syntax).
- If you add a new artifact, add both:
  - A `(copyfiles ...)` step in the script with the right `(source ...)`
    path inside the drawer and `(dest ...)` on the target filesystem.
  - A matching `install -Dm...` line in the `release` job of
    `.github/workflows/ci.yml` so the binary actually lands in the
    drawer before zipping.
