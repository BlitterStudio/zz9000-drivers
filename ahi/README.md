# ZZ9000AX audio

`zz9000ax.audio` is the AHI subdriver for ZZ9000AX PCM playback and, when the
firmware exposes its receive capability, stereo RCA recording. It sends one
16-bit stereo stream to the card after AHI has mixed the application's
channels. `mhizz9000.library` is a separate MHI library for the card's MP3
decoder.

| Component | Artifact | Installed to | Purpose |
|---|---|---|---|
| AHI subdriver | `zz9000ax.audio` | `Devs:AHI/` | PCM playback and capability-gated RCA recording. |
| AHI mode | `ZZ9000AX` | `Devs:AudioModes/` | Mode file generated by the AHI build. |
| MHI library | `mhizz9000.library` | `Libs:MHI/` | Hardware MP3 decoding for MHI-aware players. |

The current AHI driver identifies itself as `ZZ9000AX 4.32 (29.09.2026)`.
Build and installation instructions are in the [main README](../README.md).

## Set up AHI playback

1. Install `zz9000ax.audio` and the `ZZ9000AX` AudioMode file in the paths
   above.
2. Open AHI Prefs, select `ZZ9000AX`, then select a mix rate and channel
   count for the machine.
3. Save the AHI setting and select the mode in the application.

The driver advertises these AHI properties:

| Property | Value |
|---|---|
| Sample format | 16-bit signed stereo PCM |
| Mix rates | 8000, 12000, 24000, 32000, 44100, and 48000 Hz |
| AHI flags | `AHISF_KNOWSTEREO` and `AHISF_MIXING`; `AHISF_CANRECORD` when recording is available |
| Realtime attribute | `AHIDB_Realtime` is true |
| Playback buffer limit | 960 sample frames at 48 kHz (`AHIDB_MaxPlaySamples`) |
| Output | One output, `OUT 1` |
| Mixing ceiling | 8 channels (`AHIDB_MaxChannels`) |

`AHISF_MIXING` means `ahi.device` performs linear interpolation and 32-bit
accumulation on the Amiga CPU. The card receives the final stereo stream, so
channel count is a CPU limit rather than a transport limit. A 20 ms period is
mixed at the selected rate.

Use only the channels the machine can mix in time. The driver source recommends
2–4 channels at 44.1 or 48 kHz on a 68030 and advertises up to 8 for
68040-class machines. A 68060 or Apollo core can use 8 channels. When the AHI
CPU limiter skips a period, the result is audible stutter. Silent channels use
AHI's silence path.

## Record from RCA

Recording is available only when the card reports both the AX-present bit and
the receive-status capability. In that case the driver advertises
`AHIDB_Record`, `AHIDB_FullDuplex`, one input named `RCA In`, and up to 960
recording frames through `AHIDB_MaxRecordSamples`.

1. Connect the stereo source to the ZZ9000AX RCA inputs.
2. Set both ZZ9000AX auxiliary jumpers to `IN`.
3. Select `RCA In` in the recording application and select an AHI rate.
4. Start recording, or start recording and playback together from the same
   low-level AHI control.

Capture samples are `AHIST_S16S`. The input gain is fixed at `0x10000`;
`AHIC_InputGain_Query` returns that value when recording is available.
There is no monitor-volume or output-volume control. `AHIC_Input` accepts only
input index 0, `AHIC_Input_Query` returns 0, and `AHIC_MixFreq_Query` returns
the selected AHI rate.

Playback and recording can start and stop independently. Full duplex requires
`AHISF_PLAY | AHISF_RECORD` on one `AHIAudioCtrl`. A second low-level
`AllocAudio` owner cannot provide full duplex and is rejected.

Use [`ZZAXDuplexTest`](duplextest/README.md) to check the production
full-duplex path. It drives playback and recording through one `AHIAudioCtrl`;
two separate AHI clients do not exercise that path.

## AHI and MHI together

On a matched firmware and driver stack that advertises the audio fabric and
its rate capability, AHI acquires a fabric lease. The firmware converts and
mixes that lease with other fabric producers, so AHI PCM can play with MHI
music. The AHI mix-rate table stays available because the card converts the
source rate.

Without that fabric support, the legacy register path is used and AHI and MHI
are mutually exclusive. The driver detects the other owner's interrupt server
and rejects the allocation. AHI itself remains exclusive on both paths: one
`AllocAudio` owner at a time.

The legacy and fabric paths both pair every executed `PreTimer` with
`PostTimer`, including a CPU-limiter skip. The timer-pair fixture checks
recovery of complete, ordered PCM after an overload skip on both paths and
checks timer pairing without PCM delivery for oversized legacy periods.

## Firmware audio settings

With `zz9k.library` present and firmware advertising `ZZ9K_CAP_AUDIO_CONTROL`,
allocation submits the neutral source trim and release submits it again. The
firmware owns the master DSP chain, including LPF, mixer volume, and EQ. Use
ZZTop's Audio window to select scenes, set the Paula/AX baseline, and save
per-card clean ceilings.

On firmware without that capability, the driver uses legacy playback and sets
the low-pass filter to half the AHI mix rate, limited to 23900 Hz. A matched
firmware and driver pair is required for scene-owned audio settings and fabric
coexistence.

`MHIQuery(MHIQ_VOLUME_CONTROL)` advertises volume control only when matched
firmware advertises the audio control plane and the audio-stream gain service.
That control is per-stream attenuation below the active scene. MHI panning,
prefactor, and EQ calls are legacy controls; matched scene-authority firmware
reports them as unsupported rather than changing the shared DSP chain.

### Removed environment controls

| Identifier | Current behavior |
|---|---|
| `ENV:ZZ9K_MIX_LEVELS` | Ignored. The AHI and MHI drivers print a load-time debug notice when it exists. Set the baseline in ZZTop's Audio window instead. |
| `ENV:ZZ9000AX-NOLPF` | Ignored. Set the scene LPF in ZZTop's Audio window instead. |
| `AP_DSP_SET_VOLUMES` | Historical parameter used by the removed mix-level override. Current drivers do not use it for balance. |

The fallback ceilings for cards with no saved settings are Paula 48 and AX 80,
with a fallback baseline of Paula 36 and AX 72. They came from one Revision 1
card and do not establish a clean limit for another card. Saved ceilings and
baseline values take precedence. Recalibrate in ZZTop instead of raising a
ceiling to conceal distortion.

### Select the interrupt line

The driver uses INT6 (`INTB_EXTER`) by default. To use INT2 (`INTB_PORTS`),
create `ENV:ZZ9K_INT2` before the driver initializes:

```text
setenv ZZ9K_INT2 1
```

On firmware 2.3 or later, `int2 = on` in the SD card's `ZZ9000.CFG` selects
INT2 when `ENV:ZZ9K_INT2` is absent. The environment variable takes
precedence. Configure AHI and MHI the same way because their ownership check
looks at the selected interrupt list. Remove the environment variable when
migrating to the configuration-file setting.

## Hardware notes

Early ZZ9000AX Revision 1 boards have an opamp at U4 in the Paula
pass-through path. Its gain can make Paula much louder than AHI or MHI
playback. Later board revisions omit U4.

If an R1 board has this problem, desolder U4 only when equipped for SMD rework,
or set the card's clean ceilings and baseline in ZZTop. The recorded qualified
R1 pair was Paula 48 and AX 80. With the post-mix limiter, its boundary is 160;
the firmware caps each source at its own ceiling first. The former 60 boundary
for that pair predates the limiter.

## Troubleshooting

| Symptom | Action |
|---|---|
| Paula is much louder than MP3 or MOD audio | Check for an early R1 board with U4. Use the hardware repair above or calibrate the baseline and ceilings in ZZTop. |
| AHI output is muffled at low rates | On scene-authority firmware, raise the scene LPF cutoff in ZZTop. Legacy firmware uses the half-rate LPF setting. |
| ZZTop's Audio button is unavailable | The firmware does not advertise audio control, or the AX daughterboard is absent. Install the matched firmware for scene controls; playback can still work. |
| ZZTop reports `Audio: control state unavailable - retry` | Reopen Audio after the control service responds. The failed read changes no audio setting. |
| ZZTop reports `Calibration awaiting firmware state...` | Wait for the Audio window's retry, then close and reopen Audio if it remains pending. Audio edits and Save remain paused while the state is pending. |
| `Can't allocate! Hardware already used by MHI/AHI.` | Close the AHI or MHI client that owns the card. Legacy stacks allow one owner. |
| The audio device fails to open on a particular accelerator | Move both drivers to INT2 with `ENV:ZZ9K_INT2` or `int2 = on`. |
| A burst occurs before the first playback after boot | Use the current driver, which silences the DAC during allocation. |
| An AHI application has no recording option | Install firmware that reports receive status and the matching `zz9000ax.audio` driver. |
| Recording is silent | Set both auxiliary jumpers to `IN` and select `RCA In`. |
